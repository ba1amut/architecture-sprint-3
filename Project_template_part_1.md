# Задание 1. Анализ и планирование

Чтобы составить документ с описанием текущей архитектуры приложения, можно часть информации взять из описания компании условия задания. Это нормально.

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут управлять устройствами управления отопления
- Система поддерживает управление устройствами управления отопления

**Мониторинг температуры:**

- Пользователи могут получать данные с датчиков температуры
- Система поддерживает получение данных с датчиков температуры

### 2. Анализ архитектуры монолитного приложения

Архитектура приложения представляет собой монолит на Java с СУБД Postgres, предусмотрен синхронный обмен данными. Всё управление идёт от сервера к датчику. Данные о температуре также получаются через запрос от сервера к датчику.

### 3. Определение доменов и границы контекстов
Управление устройствами умного дома
Получение данных с датчиков
Управление пользователями

### **4. Проблемы монолитного решения**

- Возможно только обновление всего приложения целиком
- При кратном увеличении пользователей может замедлиться работа базы данных при возникновении очереди запросов на чтение/запись.
- При сбоях рушиться вся система и клиенты не могут получить услугу.
